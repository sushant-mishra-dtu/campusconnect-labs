# Simulation: there is no FPGA in this build

**The team does not have an iCE40 board. Every verdict in this build comes from simulation on a laptop, and every proof says so.**

The platform was designed for physical boards with an ESP32-S3 examiner wired to their pins (see [HARDWARE.md](HARDWARE.md)). Without a board, each lab node simulates one. This page explains what is simulated, how close it gets to the chip, and what it can't show.

## What a lab node runs

```
student Verilog
  → yosys synth_ice40          (WebAssembly sandbox)
  → nextpnr-ice40              (WebAssembly; UP5K, SG48, iCEBreaker pin map, 12 MHz)
  → icepack → top.bin          the bitstream a real board would be flashed with
  → icepack -u → icebox_vlog   that bitstream turned back into Verilog (readback.v)
  → iverilog + the challenge's tb.v
  → signed verdict with "kind":"sim", "target":"bitstream"
```

`labnode/src/bitstream-readback.mjs` does the part from nextpnr to `readback.v`. `icebox_vlog` is Project IceStorm's bitstream-to-Verilog converter, vendored in `labnode/vendor/icebox` (needs Python 3).

The testbench never sees the student's source. It sees what was decoded from the configuration bits of `top.bin`: every LUT's truth table, every flip-flop, carry chain and block RAM, and every routed connection between them. This is the closest a simulation gets to the chip without a board. A bug that yosys or nextpnr introduces, or a pin that was mapped wrong, shows up in the readback the same way it would on the board.

`--sim-target=netlist` on the lab node simulates yosys's gate-level netlist instead (no place and route). Those verdicts say `"target":"netlist"`.

## How it is labelled

| Where | What it says |
|---|---|
| Signed payload | `"kind":"sim"` and `"target":"bitstream"` (or `"netlist"`). Both are under the signature, so a proof can't claim more later. |
| Platform check | A `sim` examiner may only sign `netlist` or `bitstream`. Only an ESP32 the operator enrolled may sign `fpga`. Anything else is rejected. |
| Badges and proof cards | **Simulated** / **Simulated, no physical FPGA** |
| Proof page | "Simulated: the iCE40 bitstream, read back", followed by what was run, and that the signing key is on the lab node's computer |
| Attempt page | The button says **Build & simulate**, and the pipeline's flash step is **Load · into the simulator, no board** |
| Seeded lab nodes | "Simulated iCE40 UP5K (iCEBreaker pinout), no physical board" |
| Landing page | A note that no physical FPGA is attached in this demo |

Nothing in this build is labelled **Verified on silicon**. That label needs an enrolled ESP32 examiner whose verdict says `"target":"fpga"`, which needs a board.

## What the simulation can't show

The readback is a zero-delay functional model clocked by the testbench at exactly 12 MHz. It does not model:

- **Timing on the chip.** nextpnr's static timing analysis covers this instead. A design that misses 12 MHz after routing is refused before it is simulated, and the routed Fmax is printed in the live console.
- **Analog effects.** Switch bounce is generated by the testbench, not by a real switch. Metastability, I/O delays and clock jitter don't exist in the model.
- **Power-on state.** Flip-flops start at 0, the same as the iCE40 after configuration.
- **Hard blocks the readback can't decode faithfully.** These are DSP (`SB_MAC16`), SPRAM, the internal oscillators, PLLs and the I2C/SPI/LED IP. A design that uses them is refused with a message, rather than examined against a model that isn't the chip. LUTs, flip-flops, carries and block RAM (`SB_RAM40_4K`, including its initial contents) are fully modelled.
- **Trust in the examiner.** The sim examiner's key is a file on the lab node's computer, so whoever runs the node could forge a verdict. A real ESP32 examiner keeps its key on the chip. This is why sim proofs are labelled differently.

## What is real hardware today

The ESP32-S3 examiner firmware has been flashed to a real ESP32-S3. On the chip it generates its key, answers `info`, runs a challenge's test on its GPIOs and signs a v2 verdict (`"target":"fpga"`) that verifies against its public key. With no FPGA connected, it can't produce a passing verdict.

## Commands

```bash
npm run check:rtl                 # every challenge through the bitstream readback (what a sim lab node runs)
npm run check:rtl -- --netlist    # through yosys's gate-level netlist instead
npm run check:rtl -- --rtl        # the source, fastest while writing a challenge
npm run check:ice40               # every challenge builds to a UP5K bitstream that meets 12 MHz
npm run labnode                   # a sim lab node, simulating the bitstream readback
```
